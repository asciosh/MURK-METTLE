# v0.25 graphics checks

Run `npm ci`, `npm test`, `npm run build`, then `npx wrangler dev --local --port 8787`. Local accounts remain separate from production.

1. Enter the field and compare camp with the previous release. Check cloud cover, tree crowns, woven clothing, human infected silhouettes, textured ground and visible shadows.
2. Open the field menu. **Photographic surfaces** is enabled by default and should reach 4/4 when all four sets load. Inspect leaf litter and bark up close. Disable it and confirm procedural surfaces return without resetting the encounter. Re-enable it and confirm cached maps return.
3. Block `dl.polyhaven.org` in browser developer tools and reload. The game must remain playable with procedural surfaces and report fallback status. Account, map and controls must still function. The photo texture setting does not block entering the game.
4. Visit Haven (central road north, around Z -45). Inspect window framing, boarded windows, roof details, chipped plaster and rubble near foundations. Approach a wall and fire: visual detail must not change building collision or shooting cover.
5. Visit the forest and wetland. Check leaves have transparent cutouts rather than opaque rectangles, foliage wind has matching shadows, water remains visible, and distant ridges blend into the atmosphere.
6. Switch Balanced → Cinematic → Performance → Balanced. Check that all render, resize the browser and check the canvas aspect. Cinematic contact shading must preserve foliage silhouettes. Performance disables shadows; disable photo textures separately to reduce texture resolution.
7. Fire/reload both weapons, aim, sprint, bandage, use creature Pulse and defeat/restart. Check targeting and warning rings remain readable. In two different accounts, join the same room and verify player/companion appearance and combat still agree.
8. Clear several infected groups. Check the next group renders and that resource use does not increase with each cleared wave. Sign out/back in and verify saved progress remains intact.

Use the browser console to check for shader compilation errors, missing UVs, WebGL errors or failed integrity checks. CDN failures alone must not stop gameplay. Render-harness checks are useful evidence for visual import and shader compatibility, but do not measure real-device frame rate or production network reliability.

Validation for this release: 35 Node tests, TypeScript/build, local Worker co-op combat, multi-view Chromium renders in Balanced/Cinematic, photo-map replacement/reversion, blocked-download fallback and a twelve-cycle infected texture-lifetime check. Photographic render checks served previously downloaded, hash-verified original CDN bytes through the browser test route to isolate decoding/rendering from the managed environment's proxy. This does not establish live CDN delivery from a deployed game origin. The gameplay check uses the same route for photo maps.
