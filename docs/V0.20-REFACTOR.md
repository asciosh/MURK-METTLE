# Murk & Mettle v0.20 — Codebase Audit and Refactor

Source: uploaded v0.19 ZIP. This release intentionally changes **structure and maintainability**, not the save schema, gameplay balance, or the public Cloudflare URL.

## Changes shipped

1. Reorganized runtime files into browser (`src/client/game` and `src/client/ui`), Cloudflare (`server/cloudflare`), local WebSocket server (`server/local`), and pure shared multiplayer rules (`shared`).
2. Extracted remote player/companion and team pickup visuals from `Game.ts` into `CoopVisuals.ts`, including mesh lifecycle and disposal. Extracted backpack and solo crafting presentation into `FieldInventoryUI.ts`.
3. Moved HUD organization to `HudLayout.ts`; `src/main.ts` now handles boot and main menu wiring rather than panel geometry.
4. Divided the 543-line CSS into ordered `foundation.css`, `components.css`, `screens.css`, and additive `polish.css`. **Order is preserved** deliberately because CSS cascade is behavior-critical. Added keyboard-focus styles, larger mobile touch targets, safer menu scrolling, and compact-width adjustments.
5. Added `shared/coop-rules.mjs` for server-enforced mission rules, pickup geometry, zombie strain data and room input validation. Updated both the Worker and Durable Object to consume it.
6. Account API now reports a readable error if Cloudflare sends HTML instead of JSON. Field Menu closes on Escape or outside click. Corrected stale v0.16 interface labels.
7. Removed dead `CloudSave.ts` recovery-key client. Kept the historical `PlayerProfile` Durable Object class and migration: older Cloudflare namespaces cannot safely be deleted as part of a refactor.
8. Added automated contract/structure/CSS tests and archived historical changelogs under `docs/changelog/`.

## What did **not** change

- Durable Object **class names**, binding names, migration tags `v1/v2/v3`, or Worker name `murk-mettle`.
- Stored account/save keys and save revision semantics.
- Existing game room code format, websocket protocol types, mission coordinates, zombie combat balance and creature XP formula.
- Your original GLB file or model manifest.
- Account registration and PIN hashing algorithm (currently PBKDF2 with 100,000 iterations to satisfy Cloudflare limits).

## Priority findings that require later work

| Risk | Priority | Why not changed in a compatibility refactor |
|---|---|---|
| Solo XP, item quantities and crafting still calculated in browser | High | Moving solo gameplay to an authoritative simulation changes the game economy and save contract |
| PIN-only account authentication | High before public launch | Needs stronger auth, anti-abuse plan and security review; not a CSS/refactor change |
| Party extraction reward writes can fail after mission state advances | High | Requires persisted retry queue/outbox and reward reconciliation before production reliance |
| Room movement validation uses basic rate/distance bounds, not full collision authority | High for competitive/public | Needs shared server collision and anti-cheat tests |
| Persistent room mission may cross player sessions; incomplete mission recovery | Medium | Would require explicit room lifecycle policy and persistence design |
| A single `Game.ts` still owns simulation orchestration and 3D scene lighting | Medium | Incremental extraction is safer than rewiring all gameplay in one release |
| Rendering performance is not measured | Medium | Record FPS, draw calls, shadow cost and GPU memory on real browser/device |
| Original survivor GLB is a node-animated procedural model | Medium | Real rigged assets require asset authoring + animation validation |
| Legacy `PlayerProfile` Durable Object binding still exists | Low | Intentionally retained for migration history; do not drop blindly |

## Validation performed

- `npm test`: 10 tests passing.
- `node --check`: Cloudflare Worker scripts, local server and dev script pass.
- TypeScript syntax parser: all 23 TypeScript source files parsed without diagnostics.
- Archive integrity and relative import/asset checks before delivery.

**Not verified:** Full `npm run build` (npm registry unreachable), live browser gameplay, real Cloudflare worker deployment, multiplayer with 2–4 people, account save restore against production storage, performance benchmarks. These are release gates and must run in Codespaces.

## Change strategy

Deploy and verify as a single versioned application. Do not upload only browser files: the Worker main path moved. Do not delete Durable Objects, existing account information or Wrangler migrations. If a production issue arises, redeploy the previously committed v0.19 code; do not roll back stored account data blindly.
