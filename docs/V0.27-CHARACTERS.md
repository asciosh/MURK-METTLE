# v0.27 character presentation work

## Asset inspection and compatibility

The repository baseline is `75f7eea` (merged v0.26). Active implementations are in `src/client/game`; `src/game` contains compatibility exports. The authoritative room, account/save formats, shared combat rules and Cloudflare bindings are unchanged by this commit.

`public/models/survivor.glb` is the existing original v0.10 asset, 39,496 bytes, SHA-256 `0948dc886fb055da75b9da728b052651b2b0e39dcf6f67cf830c14db57abed7d`. It has 25 meshes, 3,072 triangles and 18 materials. It contains Idle, Walk, Run, Attack, Hit and Death clips, rigid node transforms, and **no skin or skeletal rig**. Its manifest was empty. Its straight rigid limbs cannot perform the current two-joint weapon, knee or bandaging poses.

The manifest now activates **equipment presentation**: pack, pack panel, beacon and belt pouch from this GLB, with rounded bounds and a field-equipment material palette at runtime. The articulated procedural body remains active for all gameplay states. The fallback pack stays visible if loading fails. Compatible full animated models remain supported when `presentation` is omitted; required clip validation is retained. Do not confuse the equipment path with full-body GLB animation or a newly authored skeletal rig.

Original binary bytes are unchanged. No new model binaries, textures, provider assets, or external art licenses are introduced. New clothing, cuffs, marker, rounded equipment adaptation, infected variation and Lanternkin facial details are original geometry authored in source for this project. Existing asset provenance is recorded in `public/models/README.md`; it describes the legacy model as programmatically authored original project art. Blender was available but was not used to claim or produce a rig. The optional game-dev CLI was unavailable; inspection used the actual GLB bytes, Three.js import and browser renders.

## Changes

- Survivor: forest-colored jacket, harness straps, layered chest pockets, zipper, cuffs and rescue marker. Head pivots at the neck, with damped look transitions. Survivor and infected rigid meshes are batched by material within individual joint groups; elbows, knees, weapon socket, healing wrap and fallback pack remain independent.
- GLB lifecycle: concurrent URL requests share source geometry/textures; SkeletonUtils clones per-actor transforms and skeletons. Materials and mixers are independent. Last-user release disposes cached resources. Late loads, rejected clips and repeated disposal are handled. `player-visual.userData.model` reports readiness or the fallback reason.
- Co-op: existing and newly joining remote survivors receive the same model entry as the local survivor, without new network messages.
- Infected: deterministic clothing/skin/head variations from existing spawn data, staggered animation phase, articulated elbows, upper-body hit recoil, and alternating collapse direction with knee/arm follow-through. Collision and damage timing are untouched.
- Companions: Lanternkin eyes, breathing leaf motion, emissive breathing and a pulse expansion shared by local and remote animation. All five species and three evolution stages remain procedural.

## Validation

Run `npm test`, `npm run typecheck`, and `npm run build`.

The optional browser regression harness requires Playwright and Chromium in the test environment (not production dependencies). Start `npm run dev:client -- --port 5173`, then run `node tests/browser/characters.cjs`. Set `ARTIFACT_DIR` to choose the capture directory, and `GAME_URL` for a different Vite origin. The script uses `/usr/bin/chromium` and software WebGL in this environment. The development-only gallery is at `/tests/browser/actor-gallery.html`; it is not a production entrypoint.

The harness renders pistol/rifle survivors, four infected strains and a companion; exercises walking, running, aiming, bandaging, attacks, hit reactions, falls and pulses; imports the legacy full-body clips; checks missing-clip rejection and disposal during loading; renders all fifteen companion forms; and captures a small landscape viewport. These are controlled visual scenarios, not real-device performance measurements.

Manual follow-up: actual Android touch play and heat/frame-rate over a full session; three PC players plus one Android in the deployed room; shooting/reloading/bandaging and companion evolution while peers join/leave; difficult camera angles and terrain foot contact. There is no terrain-aware foot locking or professional deforming skeletal rig in this change. The existing Vite bundle-size warning remains.

## Results for this change

- 42 Node tests passed, including the added GLB structure/compatibility check. Typecheck and production build passed.
- Chromium software-WebGL gallery passed without page/shader errors; required-clip rejection and disposal before a pending load resolved returned fallback and left no attached model.
- In the controlled two-survivor/four-infected/one-companion gallery, survivor and infected rigid batching removed 197 draw calls (357 to 160). The final rounded-equipment adaptation adds 768 triangles across two survivors: final gallery 58,356 triangles. This is a draw-call count, not an FPS benchmark or a comparison of whole-world performance.
- Front/back, aim and bandaging captures were inspected. Infected collapse and pulse captures are controlled pose samples; terrain and live network latency remain manual checks.

The attempt to run four fully rendered game tabs on software WebGL timed out during the second tab’s startup. This does not establish four-device performance.

A local Wrangler room check subsequently passed with **one Pixel 7 Android-emulated browser and three authenticated WebSocket protocol clients**. The browser displayed 4/4 players and rendered remote survivors. Landscape and portrait screenshots were captured; the landscape render was inspected. No page or Three.js errors were reported. This checks mixed-session connection and Android rendering, not three simultaneous PC browsers or a full combat/extraction session.
